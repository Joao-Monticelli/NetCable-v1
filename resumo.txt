# 🌐 NetCable - Mapeador Visual de Rede com Monitoramento

## 📌 1. O que é o Projeto?
O **NetCable** é uma ferramenta open-source (código aberto) projetada para ser um **Mapeador Visual de Rede (Network Topology Mapper)** com monitoramento em tempo real. 

O objetivo principal é permitir que administradores de rede criem um diagrama visual da sua infraestrutura (arrastando ícones e puxando linhas, como se fossem cabos físicos) e, ao mesmo tempo, monitorem o status desses equipamentos através de pings contínuos.

### 🎯 Principais Funcionalidades Planejadas:
1. **Interface Visual (Drag and Drop):** Criação de diagramas de rede arrastando nós.
2. **Cadastro de Equipamentos:** Definição de Nome, IP e Tipo (Switch, Roteador, Firewall, etc).
3. **Tipos Personalizados:** O usuário pode criar novos tipos de equipamentos que não estão na lista padrão.
4. **Monitoramento Real (Ping):** A ferramenta fará ping constante nos IPs cadastrados. Online = Verde, Offline = Vermelho.
5. **Hierarquia (Pai/Filho):** A direção das setas define quem depende de quem (Ex: Firewall -> Switch -> PC).
6. **Efeito Cascata (A "Mágica"):** Se um equipamento "Pai" cair, os equipamentos "Filhos" ligados a ele ficam amarelos (Aviso), indicando que estão online, mas sem conectividade com a raiz.
7. **Teste de Conexão no Cadastro:** Antes de adicionar um equipamento, o sistema testa o IP e avisa se ele está respondendo.

  O usuário agora pode alterar o tamanho de cada equipamento no mapa. Ao clicar no nó, aparecem alças (quadradinhos azuis) nas bordas, permitindo arrastar para deixar o equipamento menor (ex: um Firewall compacto) ou maior (ex: um Servidor que precisa de destaque).
  - O tamanho mínimo é de `150x60` pixels.
  - O texto do nó foi ajustado para não vazar (overflow: hidden) caso o usuário diminua muito o tamanho.
  - No Modal de Edição do Equipamento (`EquipmentModal.jsx`), foi adicionado um botão **"Restaurar Tamanho Padrão"** (que volta para `200x80`) caso o usuário faça uma bagunça e queira resetar.

- **Alças de Conexão Laterais (Handles):**
  Antes, só era possível puxar cabos para baixo. Agora, cada nó possui **4 pontas de conexão**: superior, inferior, esquerda e direita. 
  - Isso permite criar layouts mais complexos, como puxar um cabo da lateral de um Switch Gerenciável diretamente para a lateral de um Servidor.
  - O CSS foi atualizado para que as bolinhas de conexão (handles) fiquem maiores e mais visíveis (`width: 10px`, `height: 10px`, com borda escura), facilitando o clique com o mouse.

- **Lógica de Estado:** 
  O tamanho (`style: { width, height }`) agora é salvo junto com os dados do nó. Na Fase 2 (Backend), essa propriedade será enviada ao banco de dados junto com a posição (X, Y) para que o diagrama seja restaurado exatamente como o usuário deixou.

### 3.10. Reconexão de Cabos por Arrasto (Drag & Drop das Pontas)

Para tornar a edição do diagrama muito mais fluida e próxima da realidade de um software de desenho vetorial, foi implementada a funcionalidade nativa de **Reconexão de Arestas (Edge Reconnection)** do React Flow.

- **O que mudou?**
  Antes, se o usuário conectasse um cabo no equipamento errado, ele precisava excluir o cabo e criar outro do zero. Agora, é possível "pegar" a ponta do cabo e movê-la.

- **Como funciona na prática?**
  1. O usuário clica e **segura** a bolinha azul (Handle) onde o cabo está conectado ao equipamento.
  2. O cabo se "desprende" e segue o movimento do mouse.
  3. O usuário arrasta até outro equipamento e solta na bolinha de conexão dele.
  4. O cabo agora conecta os dois novos pontos automaticamente.

- **Melhorias Técnicas Aplicadas:**
  - **`edgesReconnectable={true}`:** Ativa o modo de reconexão no React Flow.
  - **`onReconnect`:** Função que captura o evento de soltar o cabo no novo local e atualiza a lista de conexões (edges) sem quebrar a referência.
  - **`reconnectRadius={20}`:** Aumenta a área de "ímã" ao redor da bolinha, facilitando acertar a ponta do cabo com o mouse (não precisa ser milimétrico).
  - **`interactionWidth: 20`:** Aumenta a área de clique da linha do cabo. Agora, se o usuário clicar em qualquer parte da linha (não só na pontinha), ele pode arrastar o cabo inteiro para outro equipamento.
  - **CSS dos Handles:** As bolinhas de conexão foram aumentadas (`12x12px`), ganharam uma borda escura (`#1e293b`) e um `z-index: 10`, garantindo que fiquem sempre por cima e fáceis de agarrar.

- **Integração com o Modal de Edição:**
  Essa funcionalidade se soma ao `EdgeModal.jsx`. O usuário tem **duas formas** de alterar uma conexão:
  1. **Visual e Rápida:** Arrastando a ponta do cabo no mapa.
  2. **Precisa:** Clicando na linha e alterando a Origem/Destino pelos selects do modal.

  ### 3.11. Conexões Laterais Livres e Estilo de Cabo Ortogonal (Fix)

Durante os testes de criação de topologias complexas, foi identificado que o React Flow estava forçando as conexões a subirem para o topo do equipamento, mesmo quando o usuário tentava puxar o cabo pelas laterais. Além disso, as curvas orgânicas (Bezier) dos cabos estavam se sobrepondo aos nós, dificultando a leitura visual da rede.

Para corrigir isso e melhorar a experiência do usuário, foram aplicadas as seguintes soluções:

- **Modo de Conexão Livre (`connectionMode="loose"`):**
  Agora, as 4 bolinhas (Handles) de cada equipamento (Topo, Base, Esquerda, Direita) funcionam tanto como ponto de partida quanto de chegada. O usuário pode puxar um cabo da lateral esquerda de um Switch e conectar na lateral esquerda de um Servidor, sem restrições de direção.

- **Identificadores Únicos nos Handles (`id="left"`, `id="right"`, etc.):**
  Foi adicionado um ID a cada bolinha. Isso ensina o React Flow a respeitar a posição exata de onde o cabo está saindo, evitando que ele "puxe" a linha para o centro ou para o topo do nó de forma automática.

- **Traço Ortogonal (`type: 'smoothstep'`):**
  O estilo padrão dos cabos foi alterado de curvas suaves (que atravessavam os nós) para **linhas ortogonais em ângulos de 90 graus**. Agora, se você puxar um cabo para o lado, ele sairá reto horizontalmente, descerá/subirá na vertical e entrará reto no outro equipamento. Isso deixa o diagrama com aparência de esquema técnico/profissional.

- **Raio de Reconexão (`reconnectRadius`):**
  Aumentamos a área de "ímã" ao redor das bolinhas. Isso significa que o usuário não precisa ser milimétrico para reconectar um cabo já existente; basta soltar o mouse perto da bolinha que o React Flow faz a conexão.

### 3.13. Fase 2: Backend (FastAPI), Banco de Dados (SQLite) e Integrações

Hoje o projeto deu um salto gigante: saiu de um protótipo visual para um sistema com persistência real de dados e monitoramento em tempo real.

#### 🐍 Backend e Banco de Dados
- **FastAPI:** O servidor Python está rodando e expondo rotas para o React.
- **SQLite & SQLAlchemy:** O banco de dados `netcable.db` foi criado. Ele armazena:
  - **Projetos:** Nome e ID.
  - **Equipamentos:** ID, Nome, IP, Tipo, Status, Tempo de Ping, Posição (X, Y), Largura e Altura.
  - **Conexões:** Origem, Destino, Rótulo, e os IDs dos Handles (bolinhas de onde o cabo sai e chega, para não perder a posição ao carregar).
- **Rotas da API:** Criadas rotas para Listar Projetos, Criar Projeto, Salvar Mapa, Carregar Dados, Excluir Projeto e Ping Real (ICMP).

#### ⚛️ Integração Frontend + Backend
- **Ping Real no Cadastro:** O botão "Testar" no modal de novo equipamento agora faz um `fetch` real para o Python, que usa a biblioteca `ping3` para testar a conexão e retorna o tempo em milissegundos (ex: `15.4ms`).
- **Monitoramento Contínuo (Polling):** O mapa React agora possui um "relógio" (setInterval) que a cada 5 segundos pergunta ao Python o status de todos os equipamentos na tela. Se a máquina cair, a bolinha fica vermelha automaticamente.
- **Salvamento e Carregamento:** O botão "Salvar" envia o JSON completo do mapa para o banco. Ao clicar em um projeto na lista, o React busca os dados no Python e redesenha o diagrama exatamente como foi salvo.

#### 🎨 Melhorias de UI/UX e Lógica Visual
- **Cores Dinâmicas e Efeito Cascata:** As linhas (edges) agora mudam de cor baseadas no status:
  - 🟢 **Verde:** Origem e destino online.
  - 🔴 **Vermelho:** Destino offline.
  - 🟡 **Amarelo (Efeito Cascata):** O equipamento "Pai" caiu (vermelho), mas o "Filho" ainda está respondendo (online). O cabo amarelo indica um alerta de falha na hierarquia superior.
  - ⚪ **Cinza:** Equipamento visual (sem IP).
- **Posicionamento Inteligente:** Ao criar um novo equipamento, ele não nasce mais no canto da tela. A função `screenToFlowPosition` calcula o centro da tela atual e posiciona o nó exatamente onde o usuário está olhando.
- **Redimensionamento por Quinas:** Ajuste no `NodeResizer` para permitir redimensionar os equipamentos apenas puxando os cantos (quinas), tanto para largura quanto para altura.
- **Contadores na Barra:** A barra superior agora exibe um resumo em tempo real: quantos equipamentos estão Online (verde), Offline (vermelho) e Sem IP (cinza).

#### 🛡️ Segurança, Backup e Compartilhamento
- **Backup (Exportar/Importar JSON):** Dois novos botões na barra permitem baixar um arquivo `.json` com todo o diagrama e importá-lo em outro projeto, servindo como backup seguro.
- **Modo de Leitura (Link Público):** 
  - No menu de **Configurações** (engrenagem), há a opção de **Gerar Link Público**.
  - O link copiado (ex: `http://localhost:5173/share/1`) abre uma tela sem barra de ferramentas, onde o usuário não pode editar, arrastar ou criar nada.
  - Porém, o monitoramento (ping e cores das linhas) continua funcionando em tempo real.
- **Logout:** A opção de "Sair" foi movida para dentro do menu de configurações.
- **Prevenção de Duplicidade:** O botão "Salvar" agora possui um estado de carregamento (loader) que o desabilita enquanto a requisição está sendo processada, evitando que cliques múltiplos criem projetos duplicados no banco.
